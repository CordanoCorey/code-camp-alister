# Run bounded maintenance with review-only source changes

Ranger Outpost Hub will use one production Cron dispatcher that claims a bounded number of due D1 jobs and source targets in deterministic order, with durable expiring leases, checkpoints, versioned rules, and idempotency keys. Maintenance Runs use an explicit system identity rather than an Operator Tenure: deterministic policy consequences may update Listing Verification lifecycle, terminal proposal privacy state, Event completion, expired security intents, and bounded history retention, while the named Service Operator remains accountable and public service continues when maintenance is delayed.

Approved Source Monitors are disabled by default and require an active Operator's exact Source Document, canonical hostname, finite mode, interval, limits, reason, and tenure approval. Technical Source Observations store only bounded metadata and fingerprints, never bodies or credentials; success never reverifies Field Provenance, and failure never proves closure or cancellation. A changed approved source creates or coalesces a private, review-only Automated Update Draft with affected fields and prior values. No current external source qualifies for a typed semantic adapter, so this slice ships no extraction or automatic-publication path.

Retries use capped exponential backoff, repeated failures open a circuit and coalesced private Automation Alert, and abandoned leases are reclaimable. This keeps D1 as the durable scheduler and audit store, avoids an orchestration dependency or external notification vendor, and lets a later run safely catch up without recursive timers or unbounded work.
